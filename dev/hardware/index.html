Hardware¶

The ADS9324's pins, supplies, reference, bus settings and timing, as the driver uses them.

All of them, with the driver API for each: Datasheet map.

The ADS9324 is a 16-channel, 16-bit, simultaneous-sampling SAR ADC. Each channel has its own clamp, programmable gain amplifier (1 MΩ input impedance) and ADC; one CONVST edge samples all 16 channels together. The registers are read and written over SPI; the conversion results come out on SDOUT (one lane) or on the D0 to D7 pins (2, 4 or 8 lanes). The driver works with the one package the datasheet lists, the 64-pin VQFN (RSK).

Typical application¶

One channel with the internal reference (REFSEL high), the data on SDOUT and the three supplies decoupled as Figure 9-4 shows. The other fifteen channels repeat the input filter of the first. The series resistors and the capacitor of the filter are values you choose: the datasheet gives the matched topology (Figure 9-2) and says to match the source resistance on both inputs, not a value.

Figure description and sources

A schematic. The MCU is on the left, each of its pins level with the chip pin it connects to; above each wire is the hook of the driver's port that drives or reads it. Supply pins point up to their supply and decoupling, ground pins down. Pins on the right carry the loads and the pins tied to a supply or ground; a cross marks a pin left open. Supplies¶

Rail Pins Range At each pin
AVDD_5V 26, 27, 56 4.75 V to 5.25 V 1 µF and 0.1 µF to GND
AVDD_1V8 30, 51 1.7 V to 1.9 V 1 µF and 0.1 µF to GND
IOVDD 34, 47 1.7 V to 3.6 V (the data timing is specified at 1.7 V to 1.9 V) 1 µF and 0.1 µF to GND

There is no required power-up order. With a 1.8 V IOVDD, AVDD_1V8 may be tied to IOVDD through a 100 Ω ferrite bead (section 9.3). Config::supply takes the rails in millivolts so Validate() can reject a value outside these ranges; leave a rail at 0 when you do not want it checked. The absolute maximum ratings (section 5.1) are documentation only: AIN pins to ±18 V, input current 10 mA, so a series resistor on every input is required when a source can exceed the rating.

Reference¶

ReferenceSource REFSEL pin Result
Pin (reset value) high Internal 4.096 V reference
Pin low External reference on REFIO
Internal ignored Internal reference
External ignored External reference on REFIO

REFIO takes 4.7 µF to REFM; REFCAPA and REFCAPB each take 1 µF (low ESR, X7R) to REFM. With the external source the reference must be 4.096 V (4.086 V to 4.106 V). SetReference() waits 30 ms for the reference to settle. The driver never drives REFSEL: tie it, or let Pin follow the board.

Control pins¶

Each control pin has a defined idle level, and the port drives it there before it enables the pin's output and before the driver's first transfer (handbook KB-HW-018): configuring a pin as an output first and setting its level afterwards gives the chip a pulse it did not ask for, a reset or a conversion.

CtrlPin Package pin Polarity Idle level Hook
Reset RESET (32) active low high (INACTIVE) GpioSet()
Convst CONVST (50) the falling edge samples; ACTIVE is high high (ACTIVE) GpioSet()
DrdyAlarm DRDY/ALARM (49) active high; Alarm::active_low inverts it an input GpioGet()

A pin tied on the board needs no hook: RESET tied high leaves Reset(ResetKind::Hardware) returning Error::Unsupported, and a CONVST driven by a timer is used with ReadFrame() instead of MeasureOnce().

Setting Value
SPI mode 0 (CPOL = 0, CPHA = 0); the datasheet names none, mode 0 follows its timing diagram (assumption A1)
Clock Up to 60 MHz for writes (kMaxClockHz); up to 29 MHz when SDOUT is read (kMaxSdoutClockHz): above it the 17 ns SDOUT delay no longer fits half a period in mode 0
Bit order MSB first
Register frame 24 bits: 8 address bits, then 16 data bits; CS low for the whole frame
Register read Select the bank (BANK_SEL), write GEN_CFG1 with the address and the read bit, then clock one frame of zeros: the reply carries the data
Data frame 16 or 24 bits per channel, up to 16 channels, plus an optional DIAG byte and a PRBS byte: at most 50 bytes
Chip select kMinCsHighNs (16 ns) high between frames; one transfer per frame

On a data readout the driver always sends zeros, so no register is written by accident while the data is clocked out (assumption A9).

The power-up and reset times are the longest the datasheet implies and are reported as ambiguous in its text (assumption A3); Limitations lists them.

Unused pins¶

The datasheet does not say how to terminate unused analog inputs or data lanes, so the driver and the figure make no claim (not verified on hardware). Bench step: with the data on SDOUT, leave D0 to D7 open and check that the self-test (RunDataPathSelfTest()) passes; for an unused input pair, read its channel with a test pattern off and check the code is stable. A floating pair in open-wire safe mode reads near zero code (section 7.3.7).
