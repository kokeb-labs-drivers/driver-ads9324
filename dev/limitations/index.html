Limitations¶

What the driver does not do, what it assumes where the datasheet is silent or contradicts itself, and what is not verified on hardware.

Datasheet sections this page relies on

From Texas Instruments SBASB22 -:

  • Open-wire safe mode: 7.3.7 Open Wire Safe Mode, p. 30
  • Block average, moving average and FIR filters: 7.3.11.2 to 7.3.11.4, p. 35
  • Daisy chain (not supported in v1): 7.3.14.2 Daisy Chain, p. 43
  • Channel registers AIN9 to AIN16 (reversed order): 8.3 AIN9 - AIN16 Channel Registers, p. 86

All of them, with the driver API for each: Datasheet map.

Out of scope: the daisy chain¶

The datasheet's daisy chain (section 7.3.14.2, Figure 7-29) shares CS and SCLK between several ADS9324 and passes each device's SDOUT to the next one's SDI. The driver leaves it out of version 1 and keeps the seam:

  • Why. In a chain a register read or write takes 32 SCLK per device instead of 24, so a single driver object cannot send one chip's frame; the frame belongs to the whole chain, with the position (DAISY_CHN_LOC) and the size (DAISY_CHN_NUM) programmed in every device. The chain works only with 1, 2 or 4 data lanes on D0 to D7, never with the data on SDOUT, which is the driver's default path. Doing it right needs a chain-level object and a host model of several chips, and neither exists yet.
  • What happens if you ask. Config::daisy exists, so the layout does not change when the support arrives; Validate() returns Error::Unsupported when daisy.enabled is set, EnsureInitialized() returns it before any I/O, the daisy-chain registers are never written, and CheckedConfig does not compile (a compile-fail test checks it).
  • What to do instead. Use one driver object per chip, each with its own chip select; the chips may share SCLK and SDI.

Behaviours to know¶

  • The randomizer's XOR_BITS_CTL code. The register table gives 0x00F1; a note in the datasheet says 0x00C1. The driver writes 0x00F1 and only that value or 0x0000. If a bench read shows a chip that wants the other value, change reg::kXorBitsRandomizer and nothing else.

  • Coverage of the datasheet. Coverage matrix lists every parameter the datasheet specifies with the symbol that covers it; rows marked GAP are values the driver has no symbol for (limits and delays that are documented in Hardware only), and tools/check_matrix.py fails when a cited symbol is missing.

  • Block average, FIR and Convert(). Convert() is one CONVST pulse. With a block-average filter on the external clock, or a FIR filter, the chip delivers a result only after the block: MeasureOnce() pulses CONVST PulsesPerResult(Filter) times; with your own timer, pulse that many times and then call ReadFrame().

  • Stuck frames are errors. A frame of all 0x00 or all 0xFF is DataMismatch by default (Sampling::reject_stuck_frames): it is what a floating SDOUT reads. Turn it off for a test pattern that really produces it.
  • One calibration at a time with a filter off. RunAdcCalibration() refuses to run with a digital filter on.
  • OrMasked alarm. The sense of the ALRM_MASK bits is not verified (A41); the call needs Alarm::or_mask_acknowledged.
  • Only documented codes. The reserved register codes are unreachable: the enumerations hold the documented values only (for example TP_MODE 1 is not offered, A22).

Some of the knobs describe the chip's behaviour only in the model (A9, A10, A17, A18, A20, A23, A25, A27, A29, A30, A32 to A34, A37, A42, A43, A45, A47): they record the assumption and no test depends on the alternative. A real chip that behaves differently shows up on the bench steps below, not in the host tests.

Not verified on hardware¶

Nothing in this driver is verified on a real ADS9324: the host tests run against a model written from the datasheet. The bench steps:

  1. EnsureInitialized() returns Ok (DEVICE_ID 0x0004) at your SPI clock; try 1 MHz first. This confirms mode 0 (A1) and the reset time (A3).
  2. RunDataPathSelfTest() passes with the inputs unconnected: the data format, the lanes and the mirrored channel mapping.
  3. Apply a known voltage to AIN9 and AIN16 and check microvolts on the right channel: the mirrored bank (A19).
  4. Run RunAdcCalibration() and check the code of a grounded input: the calibration timing (A36, A39).
  5. With 2, 4 or 8 lanes, the packing of your CaptureLanes() against SDOUT mode (the bit order is assumed).
  6. The window alert with a pulse alarm and the OrMasked source mask (A41).
